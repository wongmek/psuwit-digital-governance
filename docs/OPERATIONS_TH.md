# แนวทางบริหารระบบถาวร

## โครงสร้างผู้รับผิดชอบ

| บทบาทในระบบ | หน้าที่หลัก |
|---|---|
| `DIRECTOR` | อนุมัตินโยบาย แต่งตั้งผู้รับผิดชอบ กำหนดสิทธิ์และค่าระบบ |
| `COMMITTEE` / `DAI_EM` | กลั่นกรองคำขอและประเมินผลกระทบด้าน AI/ข้อมูล |
| `DEPARTMENT_HEAD` | รับรองความจำเป็นและกำกับรายการของหน่วยงาน |
| `DATA_OWNER` | กำหนดชั้นข้อมูล ฐานการใช้ การเข้าถึง และระยะเวลาเก็บรักษา |
| `SYSTEM_OWNER` | รับผิดชอบวงจรชีวิตระบบ ผู้ให้บริการ การเปลี่ยนแปลง และการเลิกใช้ |
| `SECURITY` | ประเมินความเสี่ยง เฝ้าระวัง รับมือเหตุ และติดตามมาตรการควบคุม |
| `AUDITOR` | อ่านรายงานและหลักฐานเพื่อตรวจสอบ |
| `USER` | ยื่นคำขอ แจ้งเหตุ และติดตามรายการของตน |

## วิธีปฏิบัติงานประจำ

1. ผู้เสนอจัดทำคำขอก่อนเริ่มใช้ AI ระบบ Cloud การแบ่งปันข้อมูล หรือการเชื่อมต่อระบบ
2. หัวหน้าหน่วยงานและผู้รับผิดชอบเฉพาะด้านตรวจความครบถ้วน ความจำเป็น ชั้นข้อมูล และความเสี่ยง
3. ผู้มีอำนาจบันทึกผลอนุมัติ เงื่อนไข หรือข้อแก้ไขในระบบ โดยไม่ใช้การตกลงนอกระบบแทนหลักฐาน
4. รายการที่อนุมัติแล้วต้องบันทึกในทะเบียนกลาง ระบุเจ้าของรายการและวันทบทวน
5. ความเสี่ยงทุกข้อกำหนดเจ้าของ มาตรการควบคุม กำหนดแล้วเสร็จ และความเสี่ยงคงเหลือ
6. ผู้พบเหตุแจ้งเหตุทันที ทีมความมั่นคงปลอดภัยคัดแยก ควบคุม กู้คืน เก็บหลักฐาน และสรุปบทเรียน
7. เอกสารประกอบเก็บใน Shared Drive ผ่านระบบ ไม่บันทึกข้อมูลลับไว้ใน GitHub

## รอบการควบคุม

| รอบ | รายการที่ต้องดำเนินการ |
|---|---|
| ทุกวันทำการ | ตรวจคำขอรอพิจารณา เหตุการณ์เปิด และรายการเร่งด่วนบน Dashboard |
| ทุกสัปดาห์ | ติดตามความเสี่ยงสูง/วิกฤต งานเกินกำหนด และความครบถ้วนของหลักฐาน |
| ทุกเดือน | ดาวน์โหลดรายงานเสนอผู้บริหาร ตรวจบัญชีผู้ดูแล และตรวจเหตุการณ์ที่ยังไม่ปิด |
| ทุกภาคเรียน | ทบทวนสิทธิ์ผู้ใช้ ทะเบียนระบบ/AI/ข้อมูล ผู้ให้บริการ และทดสอบกู้คืนข้อมูล |
| เมื่อมีการเปลี่ยนแปลงสำคัญ | ประเมินคำขอใหม่ ทบทวนความเสี่ยง และปรับหลักฐาน/ทะเบียนก่อนเปิดใช้ |

## การสำรองและกู้คืน

- กำหนดการสำรองข้อมูล TiDB ตามความสามารถของแผนบริการ และส่งออกข้อมูลสำคัญเป็น CSV รายเดือน
- สำรอง Shared Drive ตามนโยบาย Google Workspace ของโรงเรียน และจำกัดการลบถาวรแก่ผู้ดูแลจำนวนน้อย
- เก็บค่า Environment Variables ในระบบจัดการรหัสลับของหน่วยงาน ไม่เก็บในเอกสารทั่วไป
- ทดสอบกู้คืนอย่างน้อยทุกภาคเรียน โดยบันทึกวัน ผู้ทดสอบ ผล และข้อแก้ไข

ตัวอย่างสำรองเชิงตรรกะจากเครื่องที่ติดตั้ง MySQL client:

```bash
mysqldump --ssl-mode=VERIFY_IDENTITY --single-transaction --set-gtid-purged=OFF -h HOST -P 4000 -u USER -p psuwit_governance > psuwit_governance_backup.sql
```

## การรักษาความมั่นคงปลอดภัย

- บังคับใช้ MFA สำหรับ GitHub, Vercel, TiDB Cloud, Google Cloud และบัญชีผู้ดูแล Workspace
- ใช้ Service Account เฉพาะระบบและให้สิทธิ์เฉพาะ Shared Drive/โฟลเดอร์ที่จำเป็น
- หมุน `JWT_SECRET`, รหัสผ่านฐานข้อมูล และ Service Account key เมื่อสงสัยว่ารั่วไหลหรือเมื่อผู้ดูแลเปลี่ยนหน้าที่
- ตรวจ Dependabot/ผล CI ก่อนรวมโค้ด และไม่เผยแพร่เมื่อ build หรือ test ไม่ผ่าน
- Export Audit Log เก็บเป็นหลักฐานตามรอบ และตรวจการเปลี่ยนสิทธิ์ผู้ใช้ทุกครั้ง
- กำหนดผู้ประสานงานรับเหตุสำรองอย่างน้อยสองคน และมีช่องทางแจ้งเหตุนอกระบบเมื่อระบบใช้งานไม่ได้

## การจัดการการเปลี่ยนแปลง

ให้พัฒนาใน branch แยก เปิด Pull Request ตรวจทานอย่างน้อยหนึ่งคน ตรวจ CI และสำรองข้อมูลก่อน migration ทุกครั้ง การย้อนกลับให้ใช้ deployment ก่อนหน้าบน Vercel/GitHub Pages และกู้ฐานข้อมูลจากสำเนาที่ตรวจสอบแล้ว ห้ามแก้ฐานข้อมูล Production โดยไม่มีบันทึกการเปลี่ยนแปลง
