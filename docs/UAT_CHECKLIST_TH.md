# รายการตรวจรับระบบก่อนใช้งานจริง

ให้ผู้ตรวจระบุผล “ผ่าน/ไม่ผ่าน/ไม่เกี่ยวข้อง” พร้อมเลขที่หลักฐาน

| ลำดับ | รายการตรวจ | ผลที่คาดหวัง |
|---:|---|---|
| 1 | เปิด Frontend ผ่าน HTTPS | หน้าเข้าสู่ระบบแสดงผลครบถ้วนทั้งคอมพิวเตอร์และโทรศัพท์ |
| 2 | Login ด้วยบัญชี `@psuwit.ac.th` | เข้าระบบและแสดงชื่อผู้ใช้ถูกต้อง |
| 3 | Login ด้วยบัญชีนอกโดเมน | ระบบปฏิเสธการเข้าสู่ระบบ |
| 4 | ตรวจบทบาท `USER` | ไม่เห็นเมนูตั้งค่าระบบและไม่สามารถเรียก Admin API |
| 5 | ตรวจบทบาท `DIRECTOR` | กำหนดสิทธิ์และค่าระบบได้ |
| 6 | สร้างคำขอครบทุกชั้นข้อมูล | ได้เลขรับ สถานะ และคะแนนความเสี่ยง |
| 7 | พิจารณาคำขอ | บันทึกผู้พิจารณา เวลา ความเห็น และสถานะใน Timeline |
| 8 | เพิ่มทะเบียนแต่ละประเภท | ได้รหัสทะเบียน เจ้าของ และวันทบทวน |
| 9 | เพิ่มความเสี่ยง | คะแนนเท่ากับโอกาสเกิด × ผลกระทบ และจัดระดับถูกต้อง |
| 10 | แจ้งเหตุระดับวิกฤต | เหตุปรากฏบน Dashboard และทะเบียนเหตุการณ์ |
| 11 | อัปโหลดหลักฐาน | ไฟล์อยู่ใน Shared Drive และ metadata อยู่ในฐานข้อมูล |
| 12 | ดาวน์โหลดรายงานทุกประเภท | เปิด CSV ได้ ภาษาไทยไม่ผิดเพี้ยน และข้อมูลครบ |
| 13 | ตรวจ Audit Log | พบการสร้างรายการ อนุมัติ เปลี่ยนสิทธิ์ และอัปโหลด |
| 14 | ปิดฐานข้อมูลชั่วคราว | API แสดงข้อผิดพลาดโดยไม่เปิดเผยรหัสผ่านหรือ stack trace |
| 15 | ทดสอบสำรองและกู้คืน | กู้ฐานข้อมูลทดสอบและเข้าถึงหลักฐานได้ |
| 16 | ตรวจ CI | Build Frontend/Backend และ Test ผ่านทั้งหมด |

ผู้ตรวจรับควรประกอบด้วยผู้บริหาร ผู้ดูแลระบบ ผู้รับผิดชอบข้อมูล ผู้รับผิดชอบความมั่นคงปลอดภัย และผู้ใช้งานจากหน่วยงานอย่างน้อยหนึ่งราย
